## Mission

## Operating Principles

- Macro over micro: optimize for runway, burn rate, tax readiness, and peace of mind.
- Strict separation: business and personal ledgers live in the same app but remain query-isolated.

- Self-hosted first: local control, local persistence, explicit user responsibility.

### IZ-002 Israeli Bank Scraper Integration

Status: `IN PROGRESS`

**Progress (2026-07-10):** RiseUp is live as the primary transaction source. `./run-riseup.sh` → `python ingest.py riseup` imports 6 months from RiseUp's official Exposed API. Store now holds **679 transactions: 542 RiseUp (leumicard, isracard, pepperBank) + 137 Yahav**, all 542 RiseUp rows carrying a real Hebrew category. Re-running ingest inserts 0. Three findings changed the design:
- **RiseUp sees Yahav.** The spec's "sources are disjoint" premise was wrong — RiseUp returns `YahavBank` overlapping the Yahav scraper. Because `dedup_key` is source-prefixed, a naive import would have silently double-counted five months. Resolved with an explicit `OWNED_ACCOUNTS`/`DISOWNED_ACCOUNTS` map in `ingest.py`: RiseUp skips `YahavBank`, and **an account in neither map aborts the ingest** (non-zero exit) instead of being quietly imported. Yahav keeps its scraper (deeper history, real balance).
- **Category is per-transaction (`expense`), not envelope-level.** The spec said `envelope.details.categoryName`, which does not exist; the unit fixture encoded the same wrong shape, so the tests passed while every ingested row had `category = NULL`. Fixture rebuilt from the live payload. Envelope `type` is a budget bucket, not a category.
- **A timed-out month was silently dropped** — the fetch logged `skip 2026-03` and exited 0, leaving a month-shaped hole indistinguishable from a month with no spending. Now retried, then a hard non-zero exit.

Also fixed: `services/engine/Dockerfile` pinned `incomezen` to uid/gid 997. `adduser --system` had been picking a free uid at build time, so rebuilding the image reassigned it and the engine lost write access to its own DB in the `income_zen_data` volume ("attempt to write a readonly database").

**Known gap:** ingest never updates an existing row, so recategorizing a transaction inside RiseUp will not propagate on re-import (`dedup_key` excludes `category`). Fine until IZ-007 defines how source categories and user overrides reconcile.
